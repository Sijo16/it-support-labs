# Day 4 — Application Not Opening

**Learning area:** Windows application troubleshooting  
**German terminology:** Anwendung, Fehlermeldung, Task-Manager

## 1. Problem Statement

A user reports that an application was working a few minutes earlier but is now not opening.

**Objective:** Investigate the issue systematically and identify the next appropriate troubleshooting step.

## 2. Initial Questions

- Which application is affected?
- What happens when the user opens it?
- Does an error message appear?
- Does the application appear in Task Manager?
- Is the issue limited to one application or affecting multiple applications?
- Has the system or application recently been updated?

## 3. Investigation Procedure

1. Try to open the application once and observe what happens.
2. Record any error message exactly as displayed.
3. Open Task Manager using `Ctrl + Shift + Esc`.
4. Check whether the application is already running.
5. Inspect CPU and memory usage if relevant.
6. Check whether the application responds or appears unresponsive.
7. Determine whether other applications open normally.

## 4. Initial Troubleshooting Decision

If the application appears to be running already, investigate its status before launching multiple instances.

If an error appears, record the message and investigate its likely cause.

If the application does not appear in Task Manager, check the launch behaviour and relevant application information before selecting a fix.

Do not end a process, reinstall the application, or change system settings without a reason.

## 5. Findings and Status

**Scenario investigated:** Application previously used but now not opening.

**Actual error message:** Not recorded.

**Application process status:** Requires observation.

**Root cause:** Not yet confirmed.

**Resolution:** Pending further investigation and verification.

## 6. Verification Plan

After identifying and applying an appropriate fix:

1. Open the application again.
2. Confirm whether its main window appears.
3. Check whether the original function works.
4. Record the result and any remaining errors.

## 8. What I Learned

- A previously working application can fail to launch for different reasons.
- Error messages and process status provide useful diagnostic evidence.
- A structured investigation is better than immediately reinstalling software.
- A fix should only be recorded as successful after testing.

## 9. Next Learning Goal

Practise a real or safely simulated application launch problem and record the actual error, investigation, and verified outcome.

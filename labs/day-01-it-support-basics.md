# Day 1 — IT Support Fundamentals

**Learning area:** IT Support and troubleshooting
**German terminology:** IT-Support, Fehlerbehebung, Störungsmeldung

## 1. Objective

Understand the role of IT Support and learn a structured approach to investigating technical problems.

## 2. Key Concepts

* IT Support helps users resolve hardware, software, account, and network problems.
* A reported symptom is not necessarily the root cause.
* Troubleshooting should be systematic and based on evidence.
* Changes should be appropriate, safe, and documented.

## 3. Troubleshooting Workflow

1. Identify the problem (*Problem feststellen*).
2. Ask the user relevant questions (*Informationen sammeln*).
3. Gather evidence (*Daten sammeln*).
4. Identify possible causes (*Mögliche Ursachen ermitteln*).
5. Test the most likely cause (*Ursache überprüfen*).
6. Apply an appropriate solution (*Lösung anwenden*).
7. Verify the result (*Ergebnis überprüfen*).
8. Document the incident (*Störung dokumentieren*).

## 4. Example Scenario

**Reported problem:** A user says that their laptop is slow.

Before changing settings, I would ask when the problem started, whether all applications are affected, and whether any recent updates or changes occurred.

I would then inspect CPU, memory, and disk usage using Task Manager.

**Important:** These are proposed investigation steps, not a claim that the problem has already been resolved.

## 5. What I Learned

* Ask questions before attempting a fix.
* Distinguish symptoms from root causes.
* Avoid making unnecessary system changes.
* Verify and document the outcome of troubleshooting.
